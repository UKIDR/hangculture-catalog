# Электронный справочник учреждений культуры Хангаласского улуса

Готовый стартовый сайт для Управления культуры и духовного развития (УКиДР).

**Репозиторий:** https://github.com/UKIDR/hangculture-catalog  
**Адрес после публикации:** https://ukidr.github.io/hangculture-catalog/

Сайт реализован на Astro; GitHub Pages предоставляет бесплатный статический хостинг, а Pages CMS позволяет добавлять и редактировать учреждения через веб-форму. Реальные сведения в архив не включены.

## Что входит

- Главная страница, поиск по названию, наслегу и директору, фильтры по виду учреждения и наслегу.
- Отдельная страница каждого КДУ / подведомственной организации.
- Поля для фото учреждения и директора, ФИО, адреса, телефона, сайта, соцсетей, описания, истории.
- Две **демонстрационные**, вымышленные карточки (помечены «Демо»).
- Подготовленные поля для дней рождения: число, месяц и индивидуальное разрешение на публикацию. Даты пустые.
- Общий выключатель календаря дней рождения в разделе «Настройки сайта». Изначально выключен; пустой календарь не отображается.
- Автоматическая сборка и публикация GitHub Actions после изменений контента.

## Как опубликовать через GitHub Desktop (рекомендуется на Windows)

1. Установите GitHub Desktop: https://desktop.github.com/ и войдите в аккаунт **UKIDR**.
2. В программе выберите **File → Clone repository**, репозиторий `UKIDR/hangculture-catalog`, затем **Clone**.
3. Распакуйте архив из ChatGPT на компьютер.
4. Откройте папку клонированного репозитория через **Repository → Show in Explorer**.
5. Скопируйте **все файлы и папки ИЗНУТРИ распакованного архива** в папку репозитория: `src`, `public`, `.github`, `.pages.yml`, `astro.config.mjs`, `package.json`, `README.md` и `.gitignore`. Если будет предложено заменить README.md — согласитесь. **Не копируйте родительскую папку целиком**, иначе проект окажется уровнем глубже.
6. В GitHub Desktop внизу слева в поле Summary введите `Добавлен справочник учреждений культуры`, нажмите **Commit to main** и **Push origin**.
7. Откройте GitHub → репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
8. Откройте вкладку **Actions**. Дождитесь завершения `Publish directory to GitHub Pages`. После успешной публикации сайт будет доступен по адресу выше. При первом включении Pages может потребоваться повторно запустить workflow из Actions.

Если GitHub Desktop не показывает файлы `.pages.yml` или папку `.github`, проверьте, что файлы действительно скопированы: они должны находиться **в корне репозитория**.

## Как подключить Pages CMS

1. Откройте https://app.pagescms.org/.
2. Войдите через GitHub под аккаунтом **UKIDR** и предоставьте Pages CMS доступ к репозиторию `hangculture-catalog`.
3. Выберите `UKIDR / hangculture-catalog`, ветку `main`.
4. Появятся разделы **«Учреждения культуры»** и **«Настройки сайта»**.
5. В разделе «Учреждения культуры» можно создать новую запись, заполнить поля и нажать Save/Publish. Новая страница появится после завершения очередной сборки GitHub Actions.
6. Удалите две демонстрационные записи, когда внесёте настоящие учреждения.

Для нового учреждения в поле `slug` введите короткое уникальное латинское имя, например `pokrovsk-dk`. Ссылка получится `/uchrezhdeniya/pokrovsk-dk/`. Не меняйте slug опубликованного учреждения без необходимости.

## Дни рождения и безопасность

Пока **не заполняйте даты рождения**. После получения разрешений заполните день и месяц, включите `Разрешено показывать день рождения` у соответствующего руководителя и затем — `Показывать блок ближайших дней рождения` в настройках сайта. Если в ближайшие 30 дней нет согласованных дат, блок не появляется. На индивидуальных карточках даты показываются при включённых обоих переключателях.

**Это публичный репозиторий.** Не храните здесь личные номера, неразрешённые фотографии или даты рождения. Переключатель «Опубликовать на сайте = нет» скрывает карточку с веб-сайта, **но не делает запись в GitHub конфиденциальной**. Даты, для которых нет разрешения, вообще не нужно вносить в репозиторий.

## Для разработчика

```bash
npm install
npm run dev
npm run build
```

Изменение дизайна — в `public/styles.css`, главной страницы — в `src/pages/index.astro`, индивидуальной страницы — в `src/pages/uchrezhdeniya/[slug].astro`.

`astro.config.mjs` при сборке в GitHub Actions автоматически определяет базовый путь `/hangculture-catalog/` по переменной `GITHUB_REPOSITORY`.
